# 同工作区多会话分析与写入排队

新 App 和 MCP 在服务端支持 `task_queue_v1` 时默认提交排队请求。分析会话在同一目录可并行，也可观察开发任务；冲突的开发任务等待前序开发结束后开始，不同目录可并行。全自动仍取决于账号授权，不因排队改变。

## Codex 调用

`cc_start`、`cc_reply` 增加 `on_conflict`：`queue` 表示等待，`reject` 表示立即返回占用信息。省略时新客户端按服务端能力选择；直接调用 Runner RPC 省略字段保留原来的拒绝行为。旧服务端收到显式排队请求时，客户端提示更新，不伪称已经排队。

拿到 `task_id` 后继续查询原任务。`state=queued` 是已创建但未执行，不是失败；等待结果到期仍排队时返回排队状态。网络响应不确定时必须复用原 UUID，不创建另一份任务。

队列返回 `phase` 和 `queue.blocked_by`，其中列出占用任务名称及 ID。取消排队只取消这一项，不取消前序任务，不回滚文件。每账号最多32个等待任务，超过后明确提示。

## 冲突范围

相同目录及父子目录的开发写入互斥，分析之间、分析与开发兼容（文件可能被其他任务修改），按路径组件匹配，`/project/a` 不会阻挡 `/project/ab`。同一 Claude session 不允许多个活动轮次；排队和待审批也算活动。续聊保留原会话，不静默改成其他任务的后续轮次。

Git 更新从检查、获取引用到更新代码都持有远端操作租约；分支获取、文件创建/重命名/移动/回收/恢复也参与冲突保护。Git或文件操作忙时返回占用，不假装自动排队。租约 token 在客户端记录后再发请求，创建和释放可幂等恢复；活动RPC持有租约文件锁时不能人工释放。

## 断线和异常

已经启动的等待进程不依赖 SSH 连接维持。执行进程异常退出时，不自动重放已经开始的 Claude 任务。无法确认原进程是否结束时保留目录占用；重新检查后仍未知，人在 App 确认原任务停止后可释放。有存活或无法确认的进程组时拒绝释放，不直接杀进程。释放留下审计记录，不删除历史和文件。

服务器重启后的排队通过下一次状态查询恢复；没有记录完整进程身份的旧任务可能需要人工核实，不能承诺无人介入恢复。Runner更新仍要求先结束活动和排队任务，不支持带队列热升级。新 App 应与新 Runner 一起升级；旧 App 的 HOME 自检可能因父子目录保护被阻挡。

合法终态历史不参加调度。旧记录缺省字段可读取；完全损坏且无法定位目录的任务记录必须先核实恢复，错误中给出路径，不静默丢弃潜在占用。

## 分析范围与禁止修改

`cc_start`/`cc_reply`可显式指定`access="analysis"`（并行读取/搜索）或`write`（开发）。沿用现有Claude登录，不新增API、快照或OS沙箱。分析只开放受控的读取/搜索工具，不提供Bash、编辑、Agent或MCP，禁用项目设置和自定义启动入口；CLI仍维护自己的登录和会话记录。组织管理员配置的脚本不受此工具策略控制；检测到受管启动脚本或配置无法核实时拒绝分析；普通组织配置缓存不阻止分析，不能把事后init检查当作启动前屏障。

在服务器页开启“禁止 AI 修改项目文件”，服务端保存策略，App和MCP发起的Claude新任务/下一轮都受限制。显式write拒绝；省略access的新任务按analysis处理。保护关闭时省略的新任务保留write兼容；省略的续聊继承之前analysis，不自动升权。旧Runner没有能力位时不开启保护，不静默忽略analysis参数。

开启前已启动的开发不终止；排队开发暂停到保护关闭或被取消，不偷偷变成分析。关闭需用户确认并显示实际待恢复数量。MCP Git实际更新受限，dry_run允许；App人工Git与文件管理保留，但仍受目录占用保护。MCP不能设置保护，直接SSH同账号不在此保护范围。

当前受控参数支持Claude 2.1.308及以上2.1系列，工具/登录兼容仍以启动检查为准；遇额外工具、未知配置或CLI不支持明确失败，不降级成可写任务。若认证只放在项目设置中，分析不会为了登录而加载项目脚本，需先使用用户级Claude登录配置。

CLI参数语义依据 [Claude 官方 CLI reference](https://code.claude.com/docs/en/cli-reference)。官方说明help并不列出全部参数，因此参数兼容由审核版本与实际启动/init确认，不以help文本缺词判定。组织缓存文件本身不等于脚本；仅其实际脚本内容或无法解析的配置阻止分析。

初始化校验以实际工具集合、权限模式和MCP连接为准。已核实的CLI自带插件名称及命令目录可能仍出现在描述元数据中，并不因此获得工具权限；仅允许明确的builtin路径/source记录，外部插件仍拒绝。分析不提供Skill/Agent工具，命令禁用参数保持启用。
