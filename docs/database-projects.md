# 多项目数据库接入：实现决策与验收

## 用户目标与本次边界

在 CCBridge 中管理多条数据库连接，为每个项目配置多条用途映射，由远端 Claude 使用正确的命名工具。Claude 提供只读调查与方案，Codex 本地实现、编译、打包和验收。当前兼容 MySQL、PostgreSQL 和已验证的 universal-db-mcp 2.14.0。

## 已查明的安装发现问题

目标服务器的 Claude 用户配置位于 `$CLAUDE_CONFIG_DIR/.claude.json`，注册 `universal-db`，命令是 `/usr/local/bin/claude-database-mcp`。包装器引用 `/opt/claude-mcp/universal-db-mcp/node_modules/universal-db-mcp`。旧实现只在 PATH 查找 `universal-db-mcp` 可执行文件，因此漏报。

探测现读取注册的非敏感元数据，只解析包装器中的包路径字面量，不执行包装器、不返回 args/env、不读取共享数据库凭据。同时检查标准安装位置、账号目录和 nvm。发现其他版本会报告不兼容而不是未安装。

## 采用与不采用

- 采用已有 connections + 精确 workspace bindings 多对多结构，不再建立第二套项目注册；UI 使用当前项目列表。
- 保留 `--strict-mcp-config`，每个任务只挂载明确映射的连接。
- 不直接引用共享 MCP：其权限可能是 readwrite/full，代理隐藏重连工具不能使其真正只读。复用包文件，创建固定 safe 的独立连接实例。
- 不直接放宽到所有 2.x：启动器依赖内部类 API，未经版本验收不宣称兼容。当前 2.14.0 已安装，不需要升级依赖。
- 保留既有会话快照语义：新映射只影响新会话，续聊不静默切库或换凭据。任务状态返回脱敏快照与配置变更提示。
- 保留账号私有文件存储；连接和快照仍包含密码，创建临时文件起即为 0600，再原子替换。不是加密存储，服务器管理员和同一账号可读取。模型提示、MCP argv、列表响应不包含密码。

## 界面与操作

“数据库”页使用现有 shadcn/Radix 控件：连接卡片、编辑对话框、项目选择、用途别名行。连接可被多个项目引用；被引用时禁止删除。编辑密码留空保留。映射只按准确目录匹配，不自动继承父项目。

运行环境探测、协议握手、数据库认证分开：握手使用无数据库连接的同一启动器，通过 SDK 完成 initialize/tools/list，并确认动态重连工具被过滤；数据库测试真实连接，不读业务表。只读保护不替代数据库 SELECT 专用账号。

## 验收路径

1. 单元验证包装器解析、兼容版本标识、无秘密输出、私有文件权限。
2. 真实 universal-db-mcp + 临时 PostgreSQL/MySQL：两项目各两映射、连接复用、同别名独立路由、真实 SELECT、拒绝 DDL/动态改连接、账号隔离、续聊快照保留。
3. 无效数据库地址仍能通过独立 MCP 握手，证明握手没有偷连数据库。
4. Tauri 类型检查、前端构建、真实原生页面交互与服务器已有安装探测。
5. 没有提供真实业务数据库凭据时，只能报告临时库与服务器运行环境验收，不把它写成业务库已连通。
