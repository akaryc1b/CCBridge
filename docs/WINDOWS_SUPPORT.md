# Windows 后续支持范围

状态：需求已确认，尚未实现或验收。当前先完成 Mac 0.9.0 交付，Windows 不阻塞 ARM 发布和 Intel 追加。

## 交付方向

复用现有 Rust 核心、Tauri 界面和统一亮暗规范，首版以 Windows x64 为目标。提供安装程序和 GitHub 应用内更新；Windows ARM64 后续按实际需求决定。远端仍是现有 Linux SSH/Runner，不要求把远端服务迁移到 Windows。

## 必须覆盖的功能

- SSH 账号密码登录、本机保存、启动自动连接、明确的连接失败恢复。
- 全自动默认及人授权开关、任务状态、同会话续聊、实际模型显示。
- 项目/文件、分支、克隆、Git 更新、认证检测与真实进度。
- 复用 Windows 本机 Git 认证助手；缺少认证时在 App 输入保存，支持确认后同步到 VPS。
- Codex MCP 自动配置：使用当前实际安装位置生成可执行路径，不硬编码 Mac Applications 路径、用户名或项目 cwd；保留其他 MCP 配置。
- 数据库界面与现有项目映射能力保持一致，不因 Windows 接入重定义数据库权限。

## 开发时处理的平台差异

1. 先盘点 macOS 条件编译、Unix 专用 API、路径、进程信号与打包脚本，区分本机调用和 Linux 远端命令。
2. 复用现有配置目录与凭据存储边界，使用平台标准用户目录；对本机凭据文件设置 Windows 对应访问限制，不照搬 chmod 即宣称安全。
3. 本机 Git、子进程和 MCP stdio 验证空格/中文路径、参数传递、无多余控制台窗口，以及停止/退出行为。远端 Linux 命令保持原合同。
4. 安装和更新验证运行中任务保护、安装目录、用户配置保留、验签、重启与自动连接恢复；明确未做 Windows 发布者签名时的系统提示，不承诺没有提示。
5. CI 为 Windows 使用独立构建任务和缓存，并在已有发布中追加 Windows 安装包及对应更新清单平台条目；不得覆盖或删除已发布的 Mac 条目，也不让 Windows 阻塞 ARM 首发。

## 验收条件

Windows 原生环境中完成首次安装、认证复用、真实克隆/更新进度、文件恢复、全自动两轮续聊、模型显示、本机密码与重启自动连接，以及从旧版到新版的应用内签名更新。CI 编译通过不能替代 Windows 实机交互与更新验收。发布记录明确 Windows 版本和证据，不把 Mac 验收套用于 Windows。
